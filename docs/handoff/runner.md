# handoff: 실행기 (차은호)

## 맡는 범위

서비스와 무관하게 똑같이 도는 엔진. 코드에 서비스 이름(immich 등)이 나오면 안 된다.

- `wetrun/__main__.py` CLI (`run`, `check-input`, `schedule`)
- `wetrun/workflow.py` YAML 로드·검증
- `wetrun/runner.py` 단계 실행·판정·중복 실행 방지·**항상 정리**
- `wetrun/isolation.py` 전용 Compose 프로젝트·`internal` 네트워크·하드닝 옵션·정리용 라벨
- `wetrun/restic.py` restic CLI 어댑터 (`list`, `restore_subset`, `dump`, `check`)
- `wetrun/schedule.py` systemd timer·cron 설정 파일 생성
- 검증 예산(`max_bytes`·`max_minutes`), 업데이트 감지 트리거, L3

## 먼저 할 일

1. 정순준·김영모의 수동 복구 문서(`docs/manual-restore.md`)가 나오면 그 순서를 그대로 코드로 옮긴다.
   그 전에는 환경이 필요 없는 작업(YAML 스키마, restic 어댑터, lock, 예약 설정 생성)을 한다.
2. 조정민과 검사 컨테이너 계약을 11/6까지 확정해 `docs/contract.md`로 남긴다. 논의 안건은 아래.

## 계약 논의 안건 (조정민과)

1. 검사를 별도 컨테이너에서 돌릴지 (추천: 컨테이너. 격리·언어 무관)
2. 실행기가 검사에 넘길 것: 서비스 주소, `with:` 매개변수, 기준 데이터(`refs.json`) 필드, 스냅샷 파일 목록 형식, 앞 단계 결과, 부분 복원 파일 경로
3. 검사의 DB·백업 저장소 직접 접근 허용 여부 (추천: 막음. 실행기 내장 단계가 수행 후 결과만 전달)
4. 자격 증명 전달 (추천: 파일 마운트. 환경변수는 `docker inspect`에 노출) · 마스킹 책임
5. 결과 형식 (추천: 파일. stdout은 로그) · 필수 필드 · status 값
6. 종료 코드 의미 · 결과 누락/불일치 처리 · 필수 단계 skip 시 전체 결과 (추천: `inconclusive`) · 결과 합치는 우선순위
7. 실행 제한: 읽기 전용, non-root, capability 제거, 메모리·CPU·시간 기본값, 출력 크기 상한
8. 계약 버전 표시와 불일치 시 동작
9. 가짜 검사 이미지가 흉내 낼 경우 (pass·fail·timeout·깨진 결과 등), 검사 단독 실행 방법

## 지켜야 할 것

- 정리는 `finally`와 라벨 기반으로, 이번 실행이 만든 자원만 지운다. 이름이 겹친 운영 프로젝트에 `down -v`가 가면 운영 데이터가 사라진다.
- 외부 명령은 `subprocess.run([...])` 리스트 인자로만. `shell=True` 금지.
- 판정 규칙·정리 로직을 바꾸면 테스트를 같이 넣는다. 김영모가 계약 테스트로 검증한다.
- Windows·Mac에서는 systemd 실제 설치를 테스트할 수 없다. 생성 파일까지만 단위 테스트하고, 실제 설치는 Linux에서 확인한다.
