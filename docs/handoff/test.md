# handoff: 테스트·평가 (김영모)

## 맡는 범위

도구가 고장을 제대로 잡는지, 운영 서버를 건드리지 않는지 검증하고 그 결과를 평가 수치로 만든다.

- `faults/` 고장 백업 생성 스크립트와 예상 탐지 단계(정답표)
- `tests/` 계약 테스트(실행기 판정 규칙), 격리 테스트
- `eval/` 고장 시나리오 평가, 반복 실행 안정성 (성능·사용자 평가는 정순준)

## 일정

| 단계 | 할 일 |
|---|---|
| M0 (~11/6) | 11/3~4 전원 환경 세팅 참여 · 수동 복구 1회 성공·절차 문서화 (정순준과) · 운영 서버를 건드리지 않을 규칙과 확인 방법 정의 |
| M1 (~11/12) | 검사 컨테이너의 외부 통신·Docker 소켓 차단 테스트 · 고장 백업 5종 정의와 예상 탐지 단계 표 |
| M2 (~11/18) | 고장 백업 자동 생성 스크립트 · 실행기 계약 테스트 (가짜 검사로 timeout·깨진 결과 등) |
| M3 (~11/22) | 운영 서비스 공존 테스트 · 평가 계획 확정 (정순준과) |
| M4 (~11/28) | 고장 시나리오 탐지·오판정 평가 · 여러 번 돌려도 결과가 같은지 확인 |
| M5 (~12/3) | 발표자료 수정 (정순준과): 피드백 반영 내용과 평가 수치 |

## 고장 백업 5종 (초안)

| 고장 | 만드는 법 (예) | 예상 탐지 단계 |
|---|---|---|
| 원본 누락 | 기준 사진이 아닌 원본 일부를 빼고 백업 | L0 목록 대조 |
| 기준 사진 내용 변경 | 기준 사진 파일 내용을 바꿔 백업 | 해시 비교 |
| DB 덤프 손상 | 덤프 파일 일부를 잘라내거나 바꿈 | 복원·기동 |
| 필수 설정 누락 | `.env`나 compose 설정을 빼고 백업 | 입력 검사 |
| 지원 버전 불일치 | 지원 범위 밖의 이미지 태그로 기록 | 입력 검사 |

M1에서 실행기·검사 구현에 맞춰 확정하고 `faults/expected.yaml`로 남긴다. 정상 백업도 같이 돌려 실패로 판정하지 않는지(오판정) 확인한다.

## 격리·안전 테스트 항목

- 검사 컨테이너에서 외부 접속 시도 → 실패해야 함
- 검사 컨테이너에서 `/var/run/docker.sock` 접근 시도 → 실패해야 함
- 운영 Immich가 도는 호스트에서 검증 반복 실행 → 이름·포트·네트워크·볼륨 충돌 없음
- 실행 전후 운영 데이터 해시 비교 → 변경 없음
- 단계 실패·timeout·Ctrl+C 후 이번 실행이 만든 자원이 0개인지
- 로그·리포트·알림에 비밀 값이 남지 않는지

## 계약 테스트 항목

실행기 판정 규칙이 계약대로인지 가짜 검사 이미지로 확인한다 (계약 확정 후 갱신).
pass·fail·error·skip, timeout, 결과 파일 없음·깨짐, 종료 코드와 결과 불일치, 출력 크기 초과,
필수 단계 skip 시 전체가 성공으로 처리되지 않는지.

## 참고

- 이 도구에서 가장 큰 실패는 정리 단계가 운영 볼륨을 지우는 것이다. 공존 테스트는 범위를 줄일 때도 빼지 않는다.
- 공존 테스트와 최종 평가는 Linux 머신에서 한다. Docker Desktop(Windows·Mac)은 VM 안에서 돌아 결과가 다를 수 있다.
