# handoff: 검사·출력 (조정민)

## 맡는 범위

복구된 서비스를 "실제로 쓸 수 있는지" 판정하는 쪽과 결과 표현.

- `profiles/immich/` 워크플로 YAML과 검사 컨테이너 (`check/`)
- `wetrun/steps/` 내장 단계: `http_check`·`login`·`download_hash`, `db_query`, `ref_files`(L0·L2·예산 적용)
- `wetrun/report.py` 단계 결과를 JSON·요약으로 합치기, 비밀 값 마스킹
- `wetrun/notify.py` Discord 웹훅
- M4: `profiles/paperless/` (두 번째 서비스)

## 일정

| 단계 | 할 일 |
|---|---|
| M0 (~11/6) | 11/3~4 전원 환경 세팅 참여 · Immich 로그인·조회·원본 다운로드 API 확인 · DB에서 원본 경로·checksum 컬럼 확인 · 컨테이너 경로 ⇄ 스냅샷 경로 대응(`path_map`) 확인 · 검사 컨테이너 계약 합의 (차은호) |
| M1 (~11/12) | Immich 검사: 테스트 계정 로그인 → 기준 사진 조회 → 원본 다운로드 → 기대 해시 비교 |
| M2 (~11/18) | L0 목록 대조 · L2 순환 샘플링 · JSON 리포트·종료 코드 |
| M3 (~11/22) | Discord 알림(실패 단계, 원인 한 줄, 리포트 위치) · 요약 리포트 · 비밀 값 마스킹 |
| M4 (~11/28) | Paperless-ngx 프로필: **동결된 실행기를 고치지 않고** YAML과 최소 검사만으로 추가. 추가한 줄 수와 탐지 결과 기록 |
| M5 (~12/3) | 사용 설명서·워크플로 작성 가이드 (정순준) · 데모 영상 (차은호) |

## 핵심 설계 메모

- **L0**: DB가 가리키는 원본 경로 전체를 `restic ls --json` 결과와 대조. 사진 본문은 읽지 않는다. `path_map`으로 컨테이너 경로(예: `/usr/src/app/upload`)를 스냅샷 경로로 바꾸는 부분이 핵심.
- **L2**: asset ID 해시값으로 K개 버킷을 나누고 회차마다 한 버킷에서 N장을 골라 `restic dump`로 받아 해시를 계산, DB의 checksum과 비교. Immich는 중복 제거용으로 asset마다 SHA-1 checksum을 DB에 저장하므로 기대 해시를 따로 등록할 필요가 없다. 지원 버전의 실제 테이블·컬럼 이름은 M0에서 확인한다.
- **기준 사진**: DB 자체가 손상된 경우를 잡기 위해 백업 밖에 등록한 기대 해시와 비교한다. 복구 후 새로 만든 데이터로 검사를 통과시키지 않는다.
- **리포트**: 검사한 범위와 검사하지 않은 범위(예: 검색, 공유)를 반드시 적는다. L2는 이번 회차가 전체 중 어느 버킷(n/K)인지 적는다.
- **일반화 데이터 계약**: 서비스는 "DB가 가리키는 파일 경로와 checksum을 돌려주는 SQL"과 `path_map`만 선언하면 L0·L2가 동작하게 만든다. Paperless-ngx도 문서마다 checksum을 DB에 둔다(지원 버전에서 확인).

차은호와 함께 정한다. 목록은 [runner.md](runner.md#계약-논의-안건-조정민과) 참고.

## 지켜야 할 것

- `wetrun/` 안에 서비스 이름을 쓰지 않는다. Immich 고유 값(SQL, 경로, API 경로)은 `profiles/immich/`에만 둔다.
- 비밀 값(비밀번호, 토큰)은 로그·리포트·알림에 그대로 남기지 않는다.
